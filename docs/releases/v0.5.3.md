# ContextControl v0.5.3

Project autosetup now saves rules that include the detected source files, and the scanner explains what it found and what remains excluded.

- **Project Scanner:** searchable, virtualized file inventory with paths, languages, sizes, rule status and exclusion reasons. Filter all code, hidden code, included files or all discovered files; open a result directly. Scans have progress and cancellation and no fixed 20-level, 8,000-folder or 50,000-file cutoff.
- **Source precision:** recognize additional C++ include/module types, shader variants, FunC/Fift/Tolk/TL-B and other languages, named build files and extensionless scripts. Hidden and empty source files remain discoverable. Dependency packages, identified build outputs, private caches and links stay excluded. Custom skipped folders and skipped-file patterns remain in force. A generic application folder named `Dependencies` is not automatically treated as a package store.
- **Autosetup:** update and save the active project's `.ccFileRules.json`, preserve custom allowed types and explicit file exclusions, repair conflicting source-type rules, and refresh the inventory from the saved configuration. Project changes during an operation no longer redirect the refresh to another project. An incomplete or cancelled scan does not replace saved rules.
- **Allowed types and LOC:** allowed extensions control file inclusion; LOC extensions control line counting. Allowed files remain visible with zero LOC when counting is disabled, and empty source files are no longer hidden. The tree uses the saved directory rules instead of a second hardcoded project-specific allowlist.
- **Settings:** persistent navigation with vector icons, wider rule cards in two columns, clearer project scope, separate explanations for inclusion and LOC, and direct Scan / Autosetup controls. Location and export settings are grouped in a collapsible section.
- **Browser research:** recognize Google's Lithuanian consent screen and reject optional cookies when an explicit rejection button is available. Do the same for Facebook's optional-cookie dialog. Research tabs share the existing browser profile, so retained consent choices can be reused. If a recognized rejection option is unavailable, the tab requests attention without accepting optional cookies.
- **Unavailable sources:** identify Facebook login forms and authentication redirects. Consent, login and verification screens are not article evidence; the research flow continues with available public alternatives. Login-protected posts still require access and are not bypassed.
- **Local releases:** GitHub Actions is disabled and the automatic release workflow is removed. Windows installers are built, tested and uploaded locally.

Validation covers persisted autosetup rules, package/custom-exclusion handling, uncommon languages, empty/hidden files, deep paths and a source inventory exceeding 50,000 files. UI checks exercise the actual Autosetup action, large-list virtualization, settings layout and enlarged fonts. Native WebView2 fixtures exercise Lithuanian Google rejection, Facebook rejection/login detection, public content, and manual consent fallback. These fixtures validate handling; third-party pages may change or impose additional access restrictions.

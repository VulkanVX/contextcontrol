# ContextControl v0.5.6

Installed Ollama chat models can now measure CPU thread counts and supported speculative draft lengths through **Settings → LLMs → Resources → Tune speed**. This supplements the existing memory-fit planner with actual performance measurements.

- Warm each configuration, then verify a sweep winner on paired code and prose prompts. Save only repeatable improvements of at least 5% overall, with a first-text latency guard and an independent answer check.
- Match saved settings to model digest, Ollama version, hardware, context and warm GPU allocation. Keep manual opt-outs and the actual chat prompt, reasoning and sampling settings.
- Cancel at any time; new chats and transfers take priority. No weights are downloaded, no server-wide settings are changed, and existing models are not forcibly unloaded.
- Disable saved settings with **Use measured speed settings**. Stale or unmatched measurements fall back to the existing Auto planner.

On the validation laptop (Ryzen 5 5600H, RTX 3050 Ti 4 GiB, 64 GiB RAM), installed Granite 3.3 2B with Ollama 0.34.0 at 8,192 context measured 74.3 tok/s baseline and 75.2 tok/s candidate. The candidate failed the repeatability threshold, so the tuner correctly kept defaults. Qwen 3.8 27B was not fully installed and was not benchmarked. These results do not establish a theoretical maximum or a Qwen speedup.

Validation includes transport behavior, cancellation, stale-profile rejection, settings persistence, resource planning and the real settings UI. The measured tuner currently targets Ollama; other runtimes keep their existing hardware adaptation. Built and checked locally without GitHub Actions.

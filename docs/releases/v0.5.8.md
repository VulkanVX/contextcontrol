# ContextControl v0.5.8

Speed tuning now handles models such as Qwen 3.8 27B whose GPU allocation changes when speculative decoding settings change. The previous comparison rejected that legitimate change and stopped before verification.

- Check GPU allocation stability separately for each CPU/draft configuration, including repeat measurements.
- Save both verified baseline and tuned allocations, allowing a matching warm model to transition into its measured settings.
- Continue rejecting unexpected placement changes within a configuration, changed model/runtime identity, wrong context, and manual opt-outs.
- Allow the live calibration command to specify context explicitly; the app continues using the selected resource plan.

Includes v0.5.7's download fix: progressing Ollama pulls have no total-duration cutoff, transient failures resume cached data, and actual errors replace spinner text. Qwen 3.8 27B was successfully resumed and Ollama reported it installed; the packaged downloader also recognized it as complete.

On a Ryzen 5 5600H, RTX 3050 Ti 4 GiB and 64 GiB RAM, Qwen 3.8 27B with Ollama 0.34.0 at 32,768 context improved from 1.84 to 2.71 tokens/second across paired warm code/prose tests (47%). The selected configuration uses 12 CPU threads and two draft tokens; the baseline used five threads and the model's default four drafts. Both individual comparisons and the independent answer check passed. These are warm decode measurements; loading, research, reasoning length and other workloads affect total response time.

Built and checked locally without GitHub Actions. Measured improvements depend on the workload and do not prove a theoretical maximum.

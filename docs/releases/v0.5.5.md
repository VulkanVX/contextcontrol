# ContextControl v0.5.5

The hardware filter now recognizes the full bundled adaptation catalog, including quantized sizes and sizes labeled "published download". Larger models that fit through RAM offload are no longer hidden by their original full-GPU recommendation.

- Recognizes all 476 supported adaptation routes' sizes in the 544-entry bundled catalog. Size ranges use the larger endpoint; unknown sizes remain unknown.
- Explicit adapted filters work with Auto launch mode on or off. The CPU-safe filter checks CPU-only memory capacity even when partial GPU offload is also possible.
- A Resources panel in LLMs and Settings lets you preview any catalog model without downloading it or changing the chat model. It refreshes available RAM/VRAM and filters every five seconds while visible; unchanged catalog lists are retained.
- Ollama reports loaded context, total allocation and VRAM. The displayed CPU portion is derived from total minus VRAM, not measured process residency. Managed runtimes report resident process RAM, configured context, CPU threads and GPU layers; unreported VRAM stays unreported.
- A loaded Ollama candidate receives credit for its own reported allocation during fit estimation, capped by physical capacity. Other models still consume memory. Aggregate VRAM credit is applied only when a single GPU has been identified.
- Maximum context is estimated independently of the Auto target, in 1K steps, constrained by memory, known model metadata and the runtime ceiling. It is an estimate, not a verified guarantee that the runtime supports or can allocate every context length.
- "Keep free" is now called RAM/VRAM headroom, with an explanation of how it reduces the available-memory budget.

Validation covers the complete catalog, filter combinations, memory pressure, allocation credit, malformed runtime reports, metadata caching, context ceilings and UI bindings. A 64 GiB RAM / 4 GiB GPU fixture with 42 GiB free RAM, 3 GiB free VRAM and 16 GiB RAM headroom includes 387 estimated fits. Live Granite 3.3 2B checks returned the correct answer through Ollama and llama.cpp; the resource panel matched Ollama's 8,192-token active context and read its 131,072-token model limit. llama.cpp's process RAM and configured context were checked while it used CPU fallback with the GPU occupied.

No model weights were downloaded. Packages are built and checked locally without GitHub Actions. External servers, specialized runtimes, unknown metadata and architecture compatibility retain their existing limits.
